# External temporal-benchmark validation: release inspection

Inspected 3 November 2026. The upstream StreamDecisionBench scorer was subsequently reproduced offline on one authors' recording, as described below. No new model inference, TIME data redistribution, or TickLM model score on an external benchmark is claimed. The TickLM-generated suite and its small samples do not establish general temporal ability or a state-of-the-art ranking.

Three nearby 2026 sources frame the scope: [MultiTempBench](https://arxiv.org/abs/2603.19017) covers temporal arithmetic and cross-language/date-format variation; [QSTRBench](https://arxiv.org/abs/2605.18380) evaluates qualitative temporal calculi; and [TRACEBench](https://arxiv.org/abs/2607.04784) generates difficulty-controlled interval constraints. The StreamDecisionBench reproduction below checks a released streaming scorer, not these other benchmarks or a unified state-of-the-art result.

## TIME and TIME-Lite

The authors' [TIME repository](https://github.com/sylvain-wei/TIME/tree/b8cfcefdc87f22769e3b56d5c621940f5d09c5fd) describes 38,522 question-answer pairs across Wiki, News, and Dialogue, plus 943 human-reviewed TIME-Lite question-answer pairs. The current public, ungated [TIME](https://huggingface.co/datasets/SylvainWei/TIME) dataset revision observed through the Hugging Face API is `7c102e2ce1651cdfc96fdbd570dfa8cbd509d997`; the current [TIME-Lite](https://huggingface.co/datasets/SylvainWei/TIME-Lite) revision is `cd93b48ffeb8491f6d46359a8e2bf79495cb0ad3`. Both dataset cards declare CC BY 4.0. The latter's 36.5 MB `TIME-Lite.json` has published SHA-256 `6643fc42c7048fa484469ebab602ce13fd6988fb689fed90ebd7774202b8b551`. Respect attribution and license terms; no data has been copied into this repository. The GitHub API reports no recognized repository-code license at the inspected TIME revision, and no root license file appeared in its tree. The dataset-card license should not be assumed to license the repository code.

The Hugging Face dataset viewer reports the seven columns `Question`, `Gold Answer`, `Context`, `Level`, `Setting`, `Task`, and `Dataset Name`, and exposes a single source split named `train`. Its size endpoint reports **1,549 rows**, while the TIME-Lite card describes **943 question-answer pairs**. The relationship between these counts and retrieval settings was not resolved in this inspection; do not treat rows as unique questions, assume an independent test split, or report a denominator until it is reconciled. The News evaluation script includes `bm25`, `vector`, and `hybrid` settings, so setting identity must be retained when checking duplicates. The source uses both multiple-choice and free-form tasks, rather than a uniform A–D contract. The released [`utils.py`](https://github.com/sylvain-wei/TIME/blob/b8cfcefdc87f22769e3b56d5c621940f5d09c5fd/evaluation/utils.py) selects task-specific option-set metrics or free-form exact-match/token F1, including a special Wiki computation path. A TickLM score or an ad-hoc four-choice conversion is not an official TIME score.

The release is **not yet reproducible as an official end-to-end baseline** from the inspected files:

- The authors' [README](https://github.com/sylvain-wei/TIME/blob/b8cfcefdc87f22769e3b56d5c621940f5d09c5fd/README.md) explicitly says the prompt templates referenced by `evaluation/eval.py` are not included. Exact prompts materially affect the result.
- Static inspection of that revision's [`eval.py`](https://github.com/sylvain-wei/TIME/blob/b8cfcefdc87f22769e3b56d5c621940f5d09c5fd/evaluation/eval.py) shows dataset filtering using lowercase `task` and `dataset_name`, while subsequent rendering uses `Task` and `Dataset Name`; the retriever assertion also appears unconditional even for non-News settings. The supplied shell script and required command arguments need reconciliation.
- Static inspection of `utils.py` shows `compute_score` reading `all_metrics` without an assignment in that file, and `compute_score_single_case` applies option extraction twice. These are apparent implementation defects, not independently executed failure reports. The intended scorer must be confirmed against the authors' artifacts before treating a repaired implementation as equivalent.

**Next step:** locate the authors' original prompt templates and a working pinned evaluation/scoring revision or obtain clarification from an existing public release. Reconcile the 943-question/1,549-row discrepancy and News settings, and test a small manually checked set of free-form and multiple-choice outputs against the intended scorer. If a repair or substitute template is necessary, publish the patch and separately label the result as a reproduction variant. Only after that, a predeclared 100-item sample can use seed `33011`, stable source row IDs plus content hashes, and an explicit, documented sampling frame. Keep its exact original text, data revision, setting, task-specific scorer, raw outputs, failure counts, and license attribution. A 100-item subset is not a full TIME-Lite score. Because the viewer calls its only source split `train`, do not relabel the original release as an unseen held-out test set.

## StreamDecisionBench

The official [StreamDecisionBench repository](https://github.com/JacobLinCool/StreamDecisionBench/tree/a0aff621a8831c534dd210a49cd40fa14ceb14a8) at the inspected commit `a0aff621a8831c534dd210a49cd40fa14ceb14a8` declares MIT for code and data; preserve the copyright and license notice when reusing it. Its [frozen data manifest](https://github.com/JacobLinCool/StreamDecisionBench/blob/a0aff621a8831c534dd210a49cd40fa14ceb14a8/data/lite/v1/manifest.json) identifies eight 60-step scenarios across four families, with dataset hash `fdfdd55d0f304cfdd63a283ad073755750fb934d093309034d3051a5c6b7e1af`. One released episode has `schema_version`, `episode_id`, `scenario_id`, `task_family`, `questions`, `decision_spec`, `option_semantics`, and `steps`; each step has `t`, `state`, `evidence`, and `gold`. Each state contains six or seven typed choice questions that are composed into an application decision. This is not one independent A–D question per state.

The official [protocol](https://github.com/JacobLinCool/StreamDecisionBench/blob/a0aff621a8831c534dd210a49cd40fa14ceb14a8/docs/lite/PROTOCOL.md) records one state every two seconds, with overlapping requests, then reports in-force decision accuracy and normalized log-area under the curve over 0.5–8-second update intervals. Its primary replay normalizes successful attempts to release times and explicitly distinguishes this from the recorded raw wall-clock trace; the interpolation across rates assumes service latency is unchanged with request rate. Eight scenarios are not a representative sample of all deployments. The repository supplies separate offline rescoring and integrated-report commands for its published recordings; one was subsequently reproduced as described below.

### Offline reproduction on an authors' recording

A sparse checkout was pinned to `a0aff621a8831c534dd210a49cd40fa14ceb14a8`; the upstream tree was clean after scoring. The environment was isolated with `uv sync --frozen --group dev` and CPython 3.13.7. The final scorer and targeted tests ran with a clean environment (`env -i`), no inherited API credentials, one CPU thread, and no network or model calls. An initial integrated-report attempt was deliberately interrupted and restarted so the final run would use that clean environment; this was not an inference failure.

The input was the authors' existing `lite-v1-gpt-5.6-terra-none-four-family-retry-v1` recording: **eight episodes and 480 states**. Its event-log SHA-256 is `e72912b4f9aeec5a8f5d314acaecaea3ed4860f8bc91a1f9605da93b626f3561`, matching the recording manifest. Its recorded dataset hash matches the published v1 manifest, and a canonicalized comparison found all eight recorded episodes identical to the published episode files. Input and scorer file hashes were checked again after execution.

- **Targeted upstream scorer tests:** 66 passed, covering retry normalization, independent reference scoring, and interval integration. This was a targeted selection, not the entire upstream test suite.
- **Official fixed-cadence scorer:** its recomputed summary exactly matched the authors' saved `metrics.json` after excluding that file's per-episode detail. At the two-second recording cadence, release-anchored in-force accuracy was **59.847741704%** and untimed decision accuracy was **82.083333333%**. These are the upstream recorded model's results, not new model measurements.
- **Official paper report:** its normalized log-AUC over 0.5–8 seconds was **54.105400773%**, matching the published 54.11% after rounding. The entire recomputed `auc` object, including primary and sensitivity results and source hashes, exactly matched the upstream published `analysis.json`. The report's quadrature refinement difference is a numerical convergence check, not statistical uncertainty.

The local-only, Git-ignored evidence is under `artifacts/benchmark-v1-20261103/external/sdb/`: `commands.txt`, `environment.txt`, `input-sha256.txt`, `input-verification.log`, `episode-comparison-sha256.txt`, `scorer-tests-isolated.log`, `score-isolated.json`, `score-comparison-isolated.json`, `integrated/REPORT.md`, `integrated/analysis.json`, `integrated-comparison.json`, and `output-sha256.txt`. These ignored artifacts are not part of a public clone; the pinned upstream release and commands supply the reproduction path. `release-allowlist.txt` names only the small, checked evidence files, including `UPSTREAM-LICENSE`, `artifact-manifest.json`, and `release-sha256.txt`; it excludes the environment, checkout, credentials, and full recording. `integrated-analysis-public.json` retains the entire AUC object while omitting local environment metadata and other large analysis details; its AUC object was checked unchanged against the raw upstream output. Do not copy upstream data into this repository without retaining its MIT notice.

This validates that the **upstream scorer can reproduce the upstream authors' one recorded pass** in the tested environment. It does not independently validate the labels or real-world utility of the scenarios, reproduce repeated-pass uncertainty, run a TickLM model, or establish comparability with TickLM's separate benchmark.

**Next step for a new system:** implement an adapter that preserves the official multi-field choice contract, release schedule, concurrency, retry/time-accounting policy, and scorer; separately review its resource usage and shared paid-call budget before starting. A single 60-state scenario is a diagnostic, not the official eight-scenario aggregate. TickLM's current single-question live loop and its oracle-assisted reference cannot be labeled an SDB score or compared numerically with the SDB leaderboard without this protocol work.
