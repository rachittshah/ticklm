**Targeted temporal weight adaptation — experiment plan**

Date: 3 November 2026. Branch: `experiment/temporal-weight-surgery`.

Goal: test whether a small learned update improves Qwen3-0.6B's temporal decisions on held-out examples, while preserving measured non-temporal behavior. This is a weight-adaptation experiment, not a claim of intrinsic time perception or transfer of every TimesFM/Bekko capability.

**Checkpoint and rollback.** Keep the original pinned Qwen checkpoint immutable. Save adapters and derived checkpoints only beneath ignored `artifacts/` or `models/`. Commit code, configuration, compact measurements, and human-readable results. Roll back by omitting the adapter or switching to the parent branch; never overwrite the original weights. The implementation is expected to touch more than three files, so this branch and plan precede the edits.

**Experimental order.** Build and verify a causal, counterfactually paired benchmark; measure unmodified Qwen; train a small adapter; choose training settings on development data; evaluate the selected adapter once on a separate test set; run a small live-clock replay and language-retention checks. Keep all attempted development results, including failures. TimesFM and Bekko are excluded from this first intervention so gains are attributable to the changed language-model weights.

**Data contract.** `surgery_data.py` will expose `build_cases(split, pairs_per_family=32, seed=1103)`, `build_retention_cases(split="test")`, and `deterministic_answer(case)`. Cases are JSON-serializable dictionaries with `id`, `pair_id`, `split`, `family`, `prompt`, `answer` (A/B/C/D), `correct_action`, `variant`, and `state`. Prompt-visible state must contain enough information to determine the answer; labels and private metadata are never rendered. Paired cases differ in one meaningful temporal/event variable, and choice order is randomized but fixed within a pair. Splits hold out episode identities, numeric ranges, and instruction templates where practical. Document exactly what is and is not out of distribution.

Temporal families: silence duration, deadline lead time, relevance of event/plan revisions, and sustained-condition duration with explicit reset events. Supply raw timestamps and conditions, not a precomputed correct status. Labels use a deterministic reference calculation; it is a ceiling for this synthetic task and a required comparison, not evidence that an LLM is necessary. Include matched time-only and event-only counterfactual pairs. Development and final test cases must remain separate.

**Model intervention.** Use the installed MLX/MLX-LM implementation and the official Qwen3-0.6B checkpoint, pinning its resolved revision. First try rank-8 LoRA on query/value projections in a small subset of layers. Record exact trainable and total parameter counts; require less than 1% trainable parameters. Add a broader layer placement only if development results justify it. Use a scored-choice objective and record unrestricted first-token validity separately. No claim that changing 1% of parameters uses 1% of inference or training compute.

**Evaluation.** Compare identical prompts for original and adapted weights. Report per-family accuracy, paired counterfactual success, label/order robustness where implemented, unrestricted first-token validity, non-temporal retention, wall time, and memory. Always distinguish forced-choice scores from unconstrained generation probabilities. Save per-case records and runtime identity. Temporal labels must not leak through IDs, options, ordering, metadata, or precomputed state flags. Use tests for label boundaries, leakage, pair construction, split isolation, and training-mask/score correctness.

**Retention.** Hold out non-temporal multiple-choice examples and compare a small fixed set of ordinary generated answers before/after adaptation. These are smoke checks, not a broad language benchmark. If calibration or free generation degrades, report it and either reject the candidate or train with a preservation objective using training-only anchor examples. Keep that choice on development data.

**Live test.** Feed actual monotonic timestamps and changing events to the selected model. Measure action correctness as of the snapshot separately from whether the result remains valid on completion. Clock/state remain external and hard deadlines deterministic. A fast synthetic test is not a guarantee of production timing.

**Implementation ownership.** The data worker owns `surgery_data.py` and its tests/documentation. The training worker owns `surgery.py` and its tests. The parent owns integration, live demonstration, research review, results, and git checkpoints. Workers must preserve each other's changes. No one-off scripts for testing: expose experiment operations through the real package CLI and meaningful tests.

**Success boundary.** A useful outcome is a measured, reproducible improvement over the same unmodified model on these temporal tasks, with transparent retention and runtime costs. Failure to improve, or a retention regression, remains a reportable result. Full multimodal fusion and a general temporal-intelligence claim are outside this first experiment.

**Development amendment, 3 November, 06:27 UTC.** The first two candidates and the early curriculum checkpoints mostly return the same answer within counterfactual pairs. A further, separately identified input condition will supply primitive durations calculated outside the model: time since observation, remaining time before deadline, time since the latest reset, and event time relative to plan issue. Original text, thresholds, choices, and plan IDs remain present. The formatter must not supply an action, comparison result, signed threshold margin, or target-match boolean. This deliberately relaxes the raw-timestamp arithmetic requirement to isolate whether the model can use external clock measurements. Run an unadapted baseline on the identical new input condition before training; compare each input condition separately. The original raw-input results remain failures if their paired endpoint fails. This amendment is chosen using development evidence only, before final test evaluation.

**Development amendment, 3 November, before final evaluation.** The clock-feature adapter achieved 255/256 correct development answers and 127/128 correct pairs, but degraded ordinary generation. Test two preservation mechanisms: (1) periodic imitation of the frozen base model's full token distributions on separate training continuations, including the prediction after the final answer token; (2) an explicit task gate that sets the adapter contribution to zero for ordinary requests and enables it for controller-issued temporal requests. The second mechanism shares the original base tensors and must pass a real-logit and greedy-generation parity check. It is routing, not proof that the active adapter preserves general language. Every shared-model inference must enter the gate; same-thread asynchronous interleaving and compiled/cached graphs are outside this implementation's contract. Also compare a frozen linear head trained on the same curriculum and feature inputs, and a label-shuffled adapter control. Final checkpoint selection and the evaluated conditions will be locked in a separate manifest before the held-out test is run.
